# 实验任务4：定时器和 PWM 实验（一步步教学）

工程位置：**E:\led_pwm**，标准外设库（江协工程结构），两个任务编译均 0 错误 0 警告（Code=1656）。

---

## 第一步：理解任务

任务书要求两件事：

1. **定时器计数方式**：用 TIM2~TIM5 任意一个定时器，控制 LED 以 **2s 为周期**亮灭（亮 1s、灭 1s）
2. **PWM 模式**：同一个引脚改成 PWM 输出，做**呼吸灯**（渐亮渐灭，周期 1~2s），并用 **Keil 虚拟示波器观察 PWM 波形**

本工程选 **TIM2 的 CH1 通道 = PA0 引脚**（你板子上第一个 LED 就在 PA0）。两个任务做在同一个工程里，用一行宏切换：

```c
#define TASK 1		//1=任务1定时闪灯  2=任务2PWM呼吸灯
```

改这个数字 → 重新编译 → 下载，就换任务了。

## 第二步：任务1——定时器计数方式闪灯

### 2.1 定时器是什么

之前实验都是 `Delay_ms()` 软件延时——CPU 空转数数来计时，**CPU 被白白占用**。定时器是**硬件计时器**：它自己有一个计数器 CNT，每个时钟脉冲加 1，加到设定值就"到时间了"，可以产生中断通知 CPU。CPU 不用管计时，专心干别的。

### 2.2 时基单元的三个核心参数（实验报告必写）

```c
TIM_TimeBaseInitStructure.TIM_Prescaler = 7200 - 1;	//预分频 PSC
TIM_TimeBaseInitStructure.TIM_Period = 10000 - 1;	//自动重装值 ARR
```

定时器时钟频率 = **72MHz**（注意：TIM2 挂 APB1，APB1 是 36MHz，但分频系数≠1 时定时器时钟自动×2，所以还是 72MHz）

计算链条（关键公式，报告必写）：

```
定时器输入 72MHz
  ÷ PSC+1 = 7200  → 10kHz（CNT 每 0.1ms 加 1）
  ÷ ARR+1 = 10000 → 1Hz（每 1 秒数满一轮，产生"更新事件"）
```

所以 `LED 周期 = 1s × 2 次翻转 = 2s` ✓ 符合任务书。

### 2.3 更新中断的完整链条

```
CNT 数到 ARR
  → 硬件置"更新标志"(UIF)
  → 触发 TIM2_IRQn 中断
  → CPU 跳进 stm32f10x_it.c 里的 TIM2_IRQHandler()  ← 我加在 it.c 里的函数
  → 判断 TIM_GetITStatus(TIM2, TIM_IT_Update)==SET
  → GPIO 翻转 PA0（亮↔灭）
  → TIM_ClearITPendingBit 清中断标志 ← 必须清！否则刚退出又进中断
```

**注意主循环是空的**：`while(1){ }` 里什么都没有——灯闪完全靠硬件定时器 + 中断驱动。这就是"定时器计数方式"与软件延时的本质区别（对比实验一：那是 CPU 数数）。

### 2.4 为什么开 TIM2 时钟是 RCC_APB1，开 GPIOA 是 RCC_APB2

TIM2~TIM7 挂 **APB1** 总线，GPIO 挂 **APB2** 总线——两个总线时钟要分别开，漏开任何一个都不工作。

## 第三步：任务2——PWM 呼吸灯

### 3.1 PWM 是什么

**PWM（脉宽调制）**：周期固定，改变一个周期内"高电平的时间占比"（**占空比**）。LED 上人眼有视觉暂留，占空比大 → 平均电流大 → 灯亮；占空比小 → 灯暗。快速改变占空比就是呼吸灯。

### 3.2 与任务1的两处区别（报告对比点）

| | 任务1 定时闪灯 | 任务2 PWM 呼吸灯 |
|---|---|---|
| GPIO 模式 | `GPIO_Mode_Out_PP` 普通推挽 | **`GPIO_Mode_AF_PP` 复用推挽**（引脚控制权交给定时器硬件） |
| 输出单元 | 只用"更新事件"产生中断 | 用**输出比较单元**：CNT 和 CCR 比较自动出波形，全程硬件完成 |
| CPU 参与 | 中断里翻转引脚 | 主循环只负责**改 CCR**（改变占空比），波形是硬件自动生成的 |

### 3.3 PWM 的原理（核心，报告必写）

```
频率:  72MHz ÷ (PSC+1=720) ÷ (ARR+1=100) = 1kHz → 周期 1ms
波形:  CNT 从 0 数到 99，循环往复
       CNT < CCR  → 输出有效电平(高)
       CNT ≥ CCR  → 输出无效电平(低)
占空比 = CCR / (ARR+1)    例: CCR=25 → 25%
```

`TIM_SetCompare1(TIM2, i)` 就是改 CCR。主循环让 CCR 从 0→99→0，每步停 10ms：

```
199 步 × 10ms ≈ 2s = 一个完整呼吸周期 ✓ 符合任务书 1~2s
```

### 3.4 呼吸灯主循环为什么这么简单

**波形是硬件自动产生的**——CPU 只需要每隔 10ms 改一次 CCR 值，剩下的（比较、翻转引脚）全部由定时器硬件完成。这就是 PWM 的威力：不占 CPU。

## 第四步：Keil 虚拟示波器观察波形（任务书要求的重点操作）

任务书说的"虚拟示波器"就是 **Keil 逻辑分析仪（Logic Analyzer）**，用软件仿真观察引脚波形。步骤：

1. **切仿真模式**：魔术棒 → Debug 页 → 选 `Use Simulator`（不是 ST-Link！），右边勾 Dialog DLL 保持默认；Target 页确认 Xtal(MHz)=8.0
2. **编译**：F7 → 0 错误
3. **进入仿真**：Ctrl+F5（或 Debug 菜单 → Start/Stop Debug Session），确认进入后是仿真界面
4. **打开逻辑分析仪**：菜单 `View → Analysis Windows → Logic Analyzer`（MDK 5.24a 在 View 菜单下）
5. **添加信号**：点左上角 Setup 按钮 → 在输入框输入 `PORTA.0` → Enter → Close。右侧 `Display Type` 选 `Bit`
6. **运行**：F5 全速跑。任务1 会看到**方波：高 1s、低 1s**；任务2 会看到**密集的 PWM 波**，并且**波形疏密随呼吸周期渐变**（占空比小时高电平窄、占空比大时高电平宽）
7. **测周期（光标法）**：点波形窗口上方工具栏的 `Show Cycles` 和光标按钮，拖动两条竖线光标，窗口下方 `t1` 就是时间差——任务1 量半周期 ≈ **1s**；任务2 放大后量单个 PWM 周期 ≈ **1ms**（1kHz）

**两个坑**：
- 仿真速度远慢于真实硬件，任务1 的"1s"在仿真里要等十几秒甚至更久才翻转一次，**耐心等**；不想等就在 TIM2_IRQHandler 里打断点
- 任务2 刚运行那一刻 CCR=0，波形是一条直线（占空比 0%），**跑几秒**等呼吸循环开始就有波了

## 第五步：接线与下载

| 元件 | 接法 |

| LED ×1 | 接 PA0（共阳：阳极→3.3V，阴极→电阻→PA0，低电平点亮） |

任务1、任务2 用**同一个 PA0 引脚、同一根接线**，只需改 `#define TASK` 重编译。

现象：
- 任务1：LED 亮 1 秒、灭 1 秒，周期 2s

## 第六步：实验报告要点

1. **定时器频率公式**：`f = 72MHz / (PSC+1) / (ARR+1)`，任务1 代入得 1Hz（2s 周期），任务2 代入得 1kHz
2. **占空比公式**：`占空比 = CCR / (ARR+1)`
3. **三个概念**：预分频 PSC（把时钟分慢）、自动重装 ARR（一轮数几个数）、比较值 CCR（决定占空比）
4. **复用推挽** GPIO_Mode_AF_PP 的含义：引脚控制权从"输出数据寄存器"交给"片上外设（定时器）"
5. **PWM 模式1**：CNT < CCR 输出有效电平；模式2 正好相反（CNT > CCR 输出有效电平）
6. **硬件定时 vs 软件延时**对比表（报告亮点）：

| | 软件延时 Delay_ms | 定时器 |
|---|---|---|
| 计时主体 | CPU 空转数数 | 硬件计数器自动 |
| CPU 占用 | 100% | ~0% |
| 精度 | 受中断影响 | 硬件级精确 |
| 能产生波形吗 | 不能 | 能（PWM 硬件自动出波） |

7. **波形测量记录**：把逻辑分析仪光标测出的周期值填进报告（任务1 半周期≈1s，任务2 PWM 周期≈1ms）

## 常见问题排查

| 现象 | 原因与解决 |
|---|---|
| 灯不闪 | TASK 宏改对没有？重新编译没有？下载前 Debug 页切回 ST-Link 没有？ |
| 灯常亮/常灭 | 任务1 检查 TIM_ClearITPendingBit 有没有清；任务2 检查 GPIO_Mode 是不是 AF_PP（写成 Out_PP 就没有 PWM） |
| 逻辑分析仪没波形 | ①Debug 页选的是 Simulator 吗？②信号名是 PORTA.0 吗？③F5 运行了吗？④任务2 等几秒让 CCR 离开 0 |
| 波形一条直线 | 任务2 初始 CCR=0 属正常，等待呼吸循环；任务1 等一个仿真"秒" |
| 编译报 TIM2 未定义 | 检查 stm32f10x.h 里 STM32F10X_MD 宏（本工程已配好，不要动） |
| 下载报错 | Debug 页从 Simulator 切回 ST-Link Debugger |
