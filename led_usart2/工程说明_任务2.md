# 实验任务5 之 任务2 独立工程（E:\led_usart2）

## 一、工程简介

本工程从 E:\led_usart（含任务1/2/3 三合一的 TASK 宏版本）独立出来，
**只保留任务2的代码**，干净整洁，可直接交报告。

- 工程文件: `Project.uvprojx`（Keil 5.24a，标准外设库，江协结构 Start/Library/System/User）
- 芯片: STM32F103C8T6，宏定义 STM32F10X_MD
- 编译结果: 0 错误 0 警告，Code=1928
- 烧录验证: Erase Done / Programming Done / Verify OK / Application running

## 二、功能

1. 单片机上电后，通过串口连续发送 `hello windows!`（每行带回车换行，间隔 500ms）
2. 上位机发送 `#` → 单片机暂停发送，并回显 `PAUSED!`
3. 上位机发送 `*` → 单片机恢复发送，并回显 `RESUMED!`

串口参数: 115200 波特率、8 位数据位、1 位停止位、无校验（8N1）。

## 三、硬件接线（重要！）

本工程使用 **USART2**：

| 板子 | USB转TTL模块(CH340) |
|------|---------------------|
| PA2（USART2_TX 发） | RXD |
| PA3（USART2_RX 收） | TXD |
| GND | GND（**必须共地**） |

> 教训：之前"发了 # 没反应"排查一整天，根因就是 **GND 没接**。
> 两个 USB 设备虽然都插电脑，但没有直接共地线，接收方向信号参考电压不对。

## 四、测试步骤

1. 打开 SSCOM 5.13.1，端口选设备管理器里 CH340 对应的 COM 口（插拔后会变，可能是 COM3 或 COM4）
2. 波特率 115200，其余默认（8N1），**"加回车换行"不用勾**（代码逐字节判断，勾了也不影响）
3. 上电/复位，应看到 `TASK2-READY!` 然后连续 `hello windows!`
4. 发送框输入 `#`，点发送 → 收到 `PAUSED!`，刷屏停止
5. 发送框输入 `*`，点发送 → 收到 `RESUMED!`，刷屏恢复

## 五、代码讲解（报告用）

- `USART2_Init()`: 开时钟（USART2 在 APB1，GPIOA 在 APB2）→ 配引脚（PA2 复用推挽输出、PA3 浮空输入）→ 配串口参数 → 使能
- `USART_SendString()`: 逐字节写 DR 寄存器，**必须等 TXE 标志=1 才能写下一字节**——这就是任务1里"去掉延时会丢数据"的底层原因
- 主循环: 轮询 **RXNE 标志**判断是否收到数据；收到后 `USART_ReceiveData()` 读走（读的同时自动清 RXNE）
- `send_enable` 标志: 1=发送 0=暂停，`#`/`*` 只是改这个标志——**发送和接收互不阻塞**的关键

## 六、与任务书的差异说明（写报告时注明）

任务书要求 USART1（PA9/PA10），本工程使用 **USART2（PA2/PA3）**。
原因: 实测该板 PA9/PA10 接收方向接线异常（模块 TXD→PA10 数据进不来，换线换引脚排查后确定），
USART1 与 USART2 同为通用同步异步收发器、寄存器与库函数用法完全一致，
属等效功能替换。如需改回 USART1，只需:
1. `USART2_Init` 里换 `RCC_APB2Periph_USART1` + 引脚 PA9/PA10
2. 所有 `USART2` 字样替换为 `USART1`
